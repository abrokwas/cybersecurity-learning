### What I Learned

This week I focused on building a foundation in cybersecurity and understanding why security is important to individuals and organizations. One of the main concepts I studied was the **CIA Triad**, which consists of Confidentiality, Integrity, and Availability.

**Confidentiality** means protecting information from unauthorized access or disclosure. Controls such as access permissions, encryption, and authentication can help maintain confidentiality.

**Integrity** means ensuring that information remains accurate and is not changed without authorization. This is important because even if information remains confidential, unauthorized modification could make the information unreliable or potentially harmful.

**Availability** means ensuring that authorized users can access systems, services, and information when they need them. Attacks such as Denial-of-Service (DoS) can target availability by preventing legitimate users from accessing a service.

I also learned to distinguish between **threats, vulnerabilities, and risks**. A vulnerability is a weakness that could potentially be exploited, while a threat is something capable of exploiting a vulnerability or causing harm. Risk considers the likelihood of a threat successfully affecting an asset and the potential impact if it does.

Another important topic was **security controls**. Security controls are safeguards used to reduce security risks. They can include technical controls, such as firewalls and access controls; administrative controls, such as security policies and training; and physical controls, such as locks and restricted areas. I learned that effective cybersecurity normally requires multiple layers of protection rather than relying on a single control.

I also reviewed the difference between **authentication and authorization**. Authentication answers the question, **“Who are you?”**, while authorization answers, **“What are you allowed to do?”** For example, entering valid credentials can authenticate a user, while the permissions assigned to that account determine which files, applications, or systems the user is authorized to access.

The unit also introduced me to **social engineering** and how attackers can target human behaviour instead of only exploiting technical weaknesses. Techniques such as phishing, pretexting, baiting, and impersonation demonstrate why users and security awareness are important parts of an organization's overall security.

I was introduced to several categories of cyber attacks, including malware, ransomware, password attacks, denial-of-service attacks, application attacks, and network attacks. Understanding networking concepts is especially important because many attacks involve network protocols, services, ports, or communications between systems.

I also learned that attackers can have very different motivations. Threat actors can include cybercriminals, malicious insiders, hacktivists, and nation-state groups. Understanding the attacker, their motivation, and the possible attack vector can help an organization determine which risks and security controls should receive the most attention.

Finally, I learned about **security assessments, penetration testing, and threat intelligence**. Security assessments are used to identify and evaluate weaknesses. Penetration testing goes further by using authorized testing techniques to determine whether vulnerabilities can actually be exploited. Threat intelligence provides information about threats, vulnerabilities, attacker behaviour, and emerging risks that organizations can use to improve their defenses.

### Challenges

**Asset → Vulnerability → Threat → Potential Impact → Risk**

For example, a server might contain an unpatched software vulnerability. An attacker represents a potential threat that could exploit that vulnerability. The resulting possibility of unauthorized access, data loss, or service disruption contributes to the organization's risk.

Another concept I wanted to make sure I understood correctly was **authentication versus authorization**. Using the questions “Who are you?” and “What are you allowed to do?” made the distinction much easier to remember.

The number of cybersecurity terms, attacks, tools, and concepts introduced at the beginning can also be overwhelming. Instead of trying to memorize everything immediately, I am focusing on understanding the relationships between concepts and gradually reinforcing them through practical exercises.

### Key Takeaways

* The **CIA Triad — Confidentiality, Integrity, and Availability — provides a useful foundation for thinking about information security**.
* Threats, vulnerabilities, and risks are related but represent different concepts that security professionals must evaluate separately.
* Cybersecurity involves **people, processes, and technology**, not just technical tools.
* Authentication verifies identity, while authorization determines what an authenticated identity is permitted to access or perform.
* Attackers can target applications, networks, systems, and people, so effective security requires multiple layers of defense.
* Understanding an attacker's motivation and attack vectors can help organizations prioritize their defenses.
* Security assessments and authorized penetration testing help organizations discover weaknesses before malicious attackers exploit them.
* Cybersecurity requires continuous learning because technologies, vulnerabilities, and threats continue to evolve.

#### Linux and the Command Line

I learned that Linux is widely used for servers, networking, cloud infrastructure, cybersecurity tools, and security appliances. Because many cybersecurity tasks are performed on Linux systems, being comfortable with the terminal is an important foundational skill.

Instead of relying on a graphical interface, I practiced interacting with the operating system by entering commands into the shell.

Some of the basic commands I practiced included:

```bash
pwd
ls
cd
cat
echo
whoami
```

`pwd` displays the current working directory, `ls` lists files and directories, and `cd` allows me to navigate between directories. `cat` can display the contents of a file, while `whoami` identifies the current user.

#### Navigating the Linux Filesystem

I learned that Linux uses a hierarchical filesystem beginning at the root directory:

```text
/
```

Important directories include:

```text
/home
/etc
/var
/tmp
/root
/bin
```

I learned that these directories serve different purposes. For example, `/home` normally contains users' home directories, `/etc` contains system configuration files, and `/var` contains variable data such as logs.

Understanding the filesystem is particularly useful in cybersecurity because configuration files, user information, application data, and security logs are stored in different locations throughout the system.

#### Working With Files and Directories

I practiced creating, moving, copying, and deleting files and directories using commands such as:

```bash
touch
mkdir
cp
mv
rm
```

I also learned that command-line options can change the behaviour of commands and that commands commonly provide built-in documentation.

For example:

```bash
man ls
ls --help
```

This taught me that I do not need to memorize every Linux command or option. Knowing how to find documentation is an important skill in itself.

#### Searching and Filtering Information

Another important skill was learning how to locate files and search through their contents.

Commands and utilities such as:

```bash
find
grep
```

allow information to be located much more efficiently than manually searching through directories and files.

I can see this becoming particularly useful in cybersecurity when investigating configuration files, searching logs for suspicious activity, or locating files on a compromised system.

#### Shell Operators

I learned that Linux shell operators allow commands to be combined and their input or output controlled.

For example:

```bash
command1 && command2
```

can execute a second command when the first completes successfully.

Output can also be redirected:

```bash
echo "Cybersecurity Notes" > notes.txt
```

and appended without replacing the existing contents:

```bash
echo "Linux Fundamentals" >> notes.txt
```

I also began understanding the importance of pipes:

```bash
|
```

Pipes allow the output from one command to become the input for another command. This makes it possible to combine simple Linux utilities into more powerful command-line workflows.

#### Users, Groups, and Permissions

One of the most cybersecurity-relevant topics this week was **Linux permissions**.

Linux separates permissions into:

* Read (`r`)
* Write (`w`)
* Execute (`x`)

These permissions can be assigned to the file owner, group, and other users.

I used commands such as:

```bash
ls -l
chmod
```

to examine and understand file permissions.

This helped reinforce concepts from Week 1 relating to **authorization and access control**. Permissions determine what an authenticated user is allowed to do with particular system resources.

I also learned about switching users and the importance of privileged accounts. Administrative privileges should be used carefully because an account with elevated permissions can make significant changes to a system.

This connects directly with the cybersecurity principle of **least privilege**, where users and processes should receive only the permissions required to perform their tasks.

#### Processes

I learned that a **process** is a running instance of a program and that Linux provides commands for viewing and controlling processes.

Examples include:

```bash
ps
top
kill
```

I also learned about foreground and background processes and how Linux allows multiple processes to operate simultaneously.

Process monitoring has an obvious cybersecurity application. An unfamiliar or unexpected process could potentially indicate malicious software, unauthorized activity, or a compromised system.

#### Services

I was introduced to Linux services and how services can run in the background to provide functionality to the operating system and other applications.

Understanding services is important because network-facing services can increase a system's **attack surface**. A security analyst therefore needs to understand which services should be running and investigate unexpected ones.

#### Package Management

I learned that Linux distributions use package managers to install, update, and remove software.

Keeping packages updated is also a security concern because outdated software can contain known vulnerabilities that attackers may be able to exploit.

This connected Linux administration with the vulnerability-management concepts I studied during Cybersecurity Fundamentals.

#### Logs

I learned that Linux systems maintain logs containing information about system and application activity.

Logs are particularly important in cybersecurity because they can provide evidence about:

* Authentication attempts
* System activity
* Application errors
* Service activity
* Security events

This helped me understand why log analysis will become an important skill when I begin studying **Security Operations Centre (SOC)** concepts later in my learning path.

#### Automation and Scheduled Tasks

I was introduced to the idea of scheduling tasks on Linux using tools such as `cron`.

Automation can be useful for legitimate system administration activities such as backups, maintenance, scripts, and monitoring.

From a security perspective, scheduled tasks are also worth investigating because attackers who gain access to a system may attempt to establish persistence by configuring malicious commands or scripts to execute automatically.

#### SSH and Remote Access

I learned about **Secure Shell (SSH)** and its role in remotely accessing Linux systems.

SSH allows administrators and users to securely interact with remote systems through the command line.

This is especially relevant to cybersecurity because remote administration is common across servers and cloud environments. SSH therefore needs to be configured and protected appropriately.

Linux knowledge can be applied to:

### What I Learned

This week I focused on understanding **Microsoft Windows from a cybersecurity perspective**. Since Windows is widely used in business environments, understanding how Windows systems are structured, administered, and secured is important for both defensive security and security analysis.

#### Windows Fundamentals

I started by reviewing the Windows operating system and its main components. I learned more about Windows editions, the desktop environment, user accounts, file systems, permissions, and administrative functionality.

An important concept was the **NTFS file system**, which provides security capabilities such as file and folder permissions. Permissions help determine which users or groups can read, write, modify, or execute particular resources.

I also studied **User Account Control (UAC)**. UAC helps prevent programs from automatically performing administrative operations by requiring elevated privileges when necessary. This reinforces the security principle of limiting administrative access rather than allowing every process to operate with elevated privileges.

#### Windows Administration Tools

I explored several built-in Windows administration tools that can also be useful during cybersecurity investigations.

**System Configuration** provides information and configuration options relating to system startup, services, and other Windows components.

**Computer Management** brings several administrative utilities together and can be used to examine areas such as users, shared resources, storage, services, and system information.

**Task Manager** provides visibility into running applications, processes, system performance, users, and services. From a security perspective, understanding normal processes is useful because unusual processes or abnormal resource usage can sometimes provide clues during an investigation.

I also learned about the **Windows Registry**, which is a hierarchical database containing configuration information for Windows, applications, hardware, and users.

The Registry is particularly interesting from a cybersecurity perspective because legitimate applications and Windows itself depend on it, while attackers may also attempt to modify Registry entries for purposes such as persistence or system configuration changes.

#### Windows Security

Another major focus was Windows' built-in security capabilities.

I reviewed **Microsoft Defender**, which provides protection against malware and other threats, as well as **Windows Defender Firewall**, which controls network traffic according to configured rules.

I also learned about **Windows Update** and why keeping systems patched is an important security practice. Software vulnerabilities may provide attackers with opportunities to compromise systems, so applying appropriate security updates helps reduce exposure to known vulnerabilities.

These topics reinforced the idea of **defense in depth**. A Windows computer is not protected by one security mechanism alone. Permissions, authentication, antivirus/endpoint protection, firewalls, updates, policies, and user awareness all contribute to the overall security posture.

#### Event Viewer and Logging

One of the most useful topics for my cybersecurity career path was **Windows Event Viewer**.

Windows records many activities as events, and these logs can provide valuable information about what has occurred on a system. Event Viewer organizes this information into logs such as:

* Application
* Security
* System

From a defensive-security perspective, logs can help security analysts investigate activities such as authentication attempts, system changes, application problems, and other potentially suspicious behaviour.

This helped me understand why Windows event logs are important to **SOC analysts and incident responders**. Security monitoring tools and SIEM platforms can collect and correlate logs from many systems, allowing analysts to investigate suspicious activity across an organization.

---

### Active Directory Fundamentals

I also began learning about **Active Directory (AD)** and how organizations centrally manage Windows environments.

Active Directory provides a centralized way of managing identities and resources within a Windows domain.

Instead of independently configuring every computer and user account, administrators can centrally manage users, computers, groups, permissions, and policies.

#### Domains and Domain Controllers

I learned that an Active Directory **domain** represents a managed environment containing objects such as users, computers, and groups.

A **Domain Controller (DC)** is a server that provides important Active Directory services and participates in authenticating users and computers within the domain.

This makes Domain Controllers particularly important from a security perspective. If an attacker gains significant control over a Domain Controller or privileged domain account, the potential impact can extend across many systems and users within the organization.

#### Users, Groups, and Computers

Active Directory represents resources as objects.

Common objects include:

* **Users** — identities associated with people or services.
* **Groups** — collections of accounts that can be assigned permissions.
* **Computers** — machines that belong to the domain.

Groups make administration more manageable because permissions can be assigned to groups rather than individually configuring every user.

This reinforced concepts I previously studied about **authentication and authorization**. Authentication establishes identity, while authorization determines what that identity is permitted to access.

#### Organizational Units

I learned about **Organizational Units (OUs)**, which allow administrators to organize Active Directory objects logically.

For example, an organization could create separate OUs for different departments or types of computers.

This structure makes it easier to manage large environments and apply policies to appropriate groups of users or systems.

#### Group Policy

Another important concept was **Group Policy**.

**Group Policy Objects (GPOs)** allow administrators to centrally configure settings for users and computers within an Active Directory environment.

From a cybersecurity perspective, Group Policy can help organizations enforce security requirements consistently across many systems rather than depending on users to configure security settings manually.

Examples can include password-related policies, system restrictions, security settings, and other configuration requirements.

### 3. PowerShell Objects and Pipelines

One of the biggest differences I noticed between PowerShell and traditional command-line tools is how PowerShell handles data.

PowerShell works with **objects** containing properties and methods rather than treating everything only as plain text.

I also practiced using the **pipeline (`|`)** to send the output of one command to another.

For example:

```powershell
Get-Service | Where-Object Status -eq "Running"
```

This retrieves Windows services and filters the output to display services that are currently running.

Another example is:

```powershell
Get-Process | Sort-Object CPU -Descending
```

This allows process information to be sorted according to CPU usage.

I learned that filtering large amounts of information is an important command-line skill. In cybersecurity, analysts may need to examine large datasets and identify only the information relevant to an investigation.

### 7. Command Line and Cybersecurity

This unit helped me understand why command-line knowledge is a fundamental cybersecurity skill.

A cybersecurity professional may need to work with Windows workstations, Windows servers, Linux servers, cloud systems, security appliances, or remote machines where a graphical interface is unavailable or inefficient.

Command-line skills can support tasks such as:

- System enumeration
- Network troubleshooting
- Log analysis
- Incident investigation
- File analysis
- Process inspection
- Service inspection
- Security administration
- Automation
- Remote system administration

I also learned that many command-line tools are **dual-use**.

The same commands used by administrators and defenders to understand and manage systems may also be used by attackers after gaining unauthorized access.

Therefore, understanding command-line activity can help a security analyst recognize both legitimate administrative behaviour and potentially suspicious activity.

### Challenges

One of my biggest challenges was remembering the different commands used by **Windows CMD, PowerShell, and Linux**.

All three environments can perform similar tasks, but their syntax and commands can be different.

For example, listing directory contents may involve:

```text
dir
```

in Windows Command Prompt, while Linux commonly uses:

```bash
ls
```

PowerShell commonly uses:

```powershell
Get-ChildItem
```

although aliases can make some familiar commands work there as well.

Rather than trying to memorize every command, I focused on understanding the underlying task I wanted to perform and then learning how each environment performs that task.

Another challenge was understanding the **PowerShell object model**.

I was more familiar with thinking of command-line output as plain text. PowerShell's ability to pass structured objects between commands requires a different way of thinking.

Practicing pipelines and filtering helped make this concept clearer.

Linux command syntax also required careful attention. Small differences in capitalization, command options, paths, and characters can change the result of a command.

This reinforced the importance of **accuracy and attention to detail** in cybersecurity.

### Key Takeaways

- Command-line knowledge is a fundamental skill for cybersecurity professionals.
- Windows Command Prompt provides quick access to Windows system, file, process, and network information.
- PowerShell provides more advanced administration, structured data handling, scripting, and automation capabilities.
- PowerShell's Verb-Noun convention makes commands easier to understand and discover.
- `Get-Command` and `Get-Help` are valuable tools for learning PowerShell independently.
- Linux shells provide powerful ways to navigate, manage, search, and analyze systems without a graphical interface.
- Pipes allow multiple commands to be combined into more powerful workflows.
- Windows and Linux often perform similar administrative tasks using different commands and syntax.
- Command-line tools can help cybersecurity analysts investigate users, processes, files, services, networks, and system configuration.
- Command-line tools are dual-use, so understanding legitimate commands can also help identify potentially suspicious activity.
- I do not need to memorize every command; understanding how to find the appropriate command and interpret its output is more important.
