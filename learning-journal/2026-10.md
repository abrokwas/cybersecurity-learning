### What I Learned

#### Networking Concepts

I developed a stronger understanding of how computer networks operate and how devices communicate with one another. I reviewed important concepts such as IP addresses, MAC addresses, packets, frames, ports, protocols, network devices, and the different layers involved in network communication.

#### Networking Essentials

I studied the essential components that allow devices to communicate across local and external networks. This included concepts such as routing, switching, addressing, subnetting, DNS, DHCP, and the role of routers and switches.

I learned that understanding normal network behaviour is important in cybersecurity because identifying suspicious activity requires knowing what legitimate communication should look like.

I explored several protocols that are fundamental to network communication, including TCP, UDP, DNS, DHCP, ARP, and ICMP.

I learned the differences between TCP and UDP and why different applications choose one transport protocol over another. I also developed a better understanding of how DNS resolves domain names, how DHCP provides network configuration to devices, how ARP helps devices communicate on local networks, and how ICMP can be used for network diagnostics.

#### Networking Secure Protocols

I studied how secure protocols protect information transmitted across networks. This included understanding why encrypted alternatives should be preferred when sensitive information is being transmitted.

Examples included HTTPS for secure web communication, SSH for secure remote administration, and other encrypted protocols designed to protect authentication credentials and network traffic.

A key takeaway was that encryption protects data in transit and reduces the risk of credentials or sensitive information being exposed through network interception.

I practised examining packet information and using filters to focus on specific types of traffic. This helped me understand how network protocols appear in real network captures rather than only studying them theoretically.

Wireshark demonstrated how packet analysis can support troubleshooting, security monitoring, and investigations by providing detailed visibility into network communication.

#### tcpdump Basics

I learned how tcpdump can be used from the command line to capture and inspect network traffic.

Working with tcpdump helped me become more comfortable analysing network activity without relying on a graphical interface. I practised identifying interfaces, capturing packets, applying filters, and reviewing traffic relevant to an investigation.

I can see how tcpdump would be particularly useful when working with Linux servers or remote systems where a graphical tool such as Wireshark may not be available.

#### Nmap Basics

I was introduced to Nmap as a network discovery and security assessment tool.

I practised using Nmap in authorized lab environments to identify hosts, open ports, and services running on systems. I also learned how scan results can help a security analyst understand a system's exposed network services and identify areas that may require further investigation.

This reinforced the importance of ports and services in network security and showed how network enumeration can contribute to both defensive security assessments and authorized penetration testing.

### What I Learned

#### Cryptography Basics

I developed a better understanding of cryptography and its role in cybersecurity. Cryptography is used to protect information from unauthorized access and helps provide confidentiality, integrity, authentication, and non-repudiation.

I learned the difference between plaintext and ciphertext and how encryption transforms readable information into an unreadable format using a cryptographic algorithm and key.

I also studied symmetric encryption, where the same secret key is used to encrypt and decrypt information. Symmetric encryption is efficient for protecting large amounts of data, but securely exchanging the secret key between parties can present a challenge.

This helped me understand that cryptography is not simply about hiding information; it is an important part of securing communications, stored data, authentication systems, and many other technologies.

#### Public Key Cryptography Basics

I studied asymmetric, or public key, cryptography and learned how it differs from symmetric encryption.

Instead of using one shared secret key, asymmetric cryptography uses a pair of mathematically related keys:

- **Public key** — can be shared with others.
- **Private key** — must remain protected by its owner.

I learned that public key cryptography can be used for secure key exchange, authentication, encryption, and digital signatures.

I also developed a better understanding of how asymmetric and symmetric encryption can work together. Public key cryptography can help establish or exchange secret information securely, while symmetric encryption can then efficiently protect larger amounts of data.

This gave me greater insight into the cryptographic concepts behind technologies such as HTTPS, TLS, SSH, certificates, and secure online communication.

#### Hashing Basics

I learned that hashing is different from encryption.

A cryptographic hash function takes input data and produces a fixed-size output known as a hash or digest. Unlike encryption, hashing is designed to be a one-way process and is not intended to be reversed to recover the original information.

I studied how hashes can be used to verify data integrity. If even a small part of a file or message changes, its resulting hash should also change, allowing modifications to be detected.

I also learned how hashing is used in password storage. Instead of storing passwords directly as plaintext, systems can store password hashes and compare them during authentication.

I learned about the importance of techniques such as salting passwords, which helps make attacks using precomputed hash databases more difficult.

This topic demonstrated why secure password storage requires more than simply applying a basic hash function.

#### John the Ripper Basics

I gained introductory hands-on experience with John the Ripper, a password auditing and recovery tool.

Using authorized TryHackMe lab environments, I learned how John the Ripper can test password hashes against possible passwords and demonstrate the risks associated with weak passwords.

I practised working with hash data, using wordlists, and interpreting the results produced by the tool.

This exercise demonstrated that even when passwords are stored as hashes, weak or predictable passwords may still be discovered through password-cracking techniques.

John the Ripper also helped connect the theoretical concepts I learned about hashing with a practical cybersecurity use case.

### Hands-On Practice

During the TryHackMe labs, I applied the cryptography concepts through practical exercises.

My activities included:

- Identifying differences between symmetric and asymmetric cryptography
- Exploring public and private key concepts

These exercises helped me move beyond definitions and understand how cryptography is applied in real cybersecurity scenarios.

### Challenges

One challenge was distinguishing between encryption, encoding, and hashing because they can initially appear to perform similar transformations on data. I now understand that they have different purposes and security properties.

Another challenge was understanding how public and private keys interact in different situations. Continued practice with certificates, SSH, and TLS should help reinforce these concepts.

Working with password hashes also required careful attention to hash formats and the tools used to process them. I would like to continue practising hash identification and password auditing in legal training environments.

### Key Takeaways

My biggest takeaway from this module is that cryptography provides several different mechanisms for protecting information, and each mechanism serves a different purpose.

**Symmetric encryption** provides efficient encryption using a shared secret key, while **asymmetric encryption** uses public and private keys and enables capabilities such as secure key exchange and digital signatures.

**Hashing** is designed to produce a one-way representation of information and is useful for integrity verification and secure password-storage systems.




I also learned through John the Ripper that cryptographic protection cannot compensate for weak passwords. Strong password practices and secure password-storage techniques remain important parts of an organization's security.

Understanding these concepts gives me a stronger foundation for studying authentication, TLS/HTTPS, certificates, digital signatures, password security, vulnerability assessment, and security monitoring.

### 1. Topics Studied

### 2. What I Learned

#### A. Moniker Link

I studied the Moniker Link vulnerability, **CVE-2024-21413**, which affects Microsoft Outlook.

**Key learning points:**
- How specially crafted links can bypass certain Outlook security protections.
- How phishing emails can exploit application vulnerabilities.
- How malicious links can expose authentication information.
- Why security updates, email filtering, and user awareness are important.

**Security takeaway:** Even trusted applications can contain vulnerabilities that attackers exploit through social engineering.

#### B. Metasploit Introduction

I explored the Metasploit Framework and its role in penetration testing and vulnerability assessment.

**Key learning points:**
- The purpose of Metasploit and its main components.
- The difference between exploits, payloads, auxiliary modules, and post-exploitation modules.
- How to search for modules and examine their configuration.
- Why vulnerability validation should be performed only in authorized environments.

**Commands studied:**

```bash
msfconsole
help
search smb
info <module_name>
use <module_path>
show options
show payloads
back
exit
```

**Security takeaway:** Metasploit provides a structured environment for investigating and validating security weaknesses.

#### C. Metasploit Exploitation

I studied how a penetration tester moves from identifying a vulnerable service to selecting and configuring a suitable Metasploit module.

**Key learning points:**
- Identifying services and potential vulnerabilities.
- Matching exploit modules to target software and versions.
- Understanding module options such as `RHOSTS`, `RPORT`, and `LHOST`.
- Understanding the role of payloads and handlers.
- Recognizing the importance of documenting findings and remediation steps.

**Commands studied:**

```bash
search <keyword>
use <module_path>
show options
set RHOSTS <lab_target_ip>
check
```

The `check` command can help assess vulnerability status when supported by the selected module.

**Security takeaway:** Successful vulnerability assessment depends on accurate reconnaissance, careful module selection, and understanding the risks associated with exploitation.

#### D. Metasploit Meterpreter (Interpreter)

I learned about Meterpreter, an advanced Metasploit payload that supports interaction with compromised systems in controlled penetration-testing environments.

**Key learning points:**
- The difference between a standard command shell and Meterpreter.
- How Metasploit manages active sessions.
- Why post-exploitation activities are sensitive and must remain within an authorized scope.
- How defenders can investigate unusual processes, network connections, and account activity.

**Commands studied:**

```bash
sessions -l
sessions -i <session_id>
background
sysinfo
getuid
```

**Security takeaway:** Understanding Meterpreter helps security professionals recognize the kinds of activity that may follow an initial compromise.

#### E. Blue

I studied the **EternalBlue vulnerability (MS17-010)** and its relationship to Windows SMB security.

**Key learning points:**
- How vulnerabilities in network services can expose systems to remote attacks.
- Why SMB services should be carefully configured and monitored.
- The importance of applying Microsoft security updates.
- How unsupported operating systems increase organizational risk.
- Why network segmentation and restricted SMB access reduce exposure.

**Security takeaway:** Unpatched network services can create serious security risks, particularly when vulnerable systems are reachable across a network.

#### F. TShark Challenge I: Teamwork

I explored TShark as a command-line tool for inspecting packet captures and investigating network traffic.

**Key learning points:**
- Reading packet capture files.
- Filtering traffic by protocol, IP address, and port.
- Investigating suspicious communication patterns.
- Extracting relevant details from captured packets.
- Understanding how network evidence supports incident investigations.

**Commands studied:**

```bash
tshark -r capture.pcap
tshark -r capture.pcap -q -z io,phs
tshark -r capture.pcap -Y "dns"
tshark -r capture.pcap -Y "http"
tshark -r capture.pcap -Y "tcp"
tshark -r capture.pcap -Y "ip.addr == 192.168.1.10"
```

**Security takeaway:** Packet analysis is an important defensive skill for identifying suspicious connections and reconstructing network activity.
