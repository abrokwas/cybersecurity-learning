#### B. SOC Fundamentals

I explored how a Security Operations Centre operates and how SOC analysts monitor and investigate potential cybersecurity threats.

**Key learning points:**

- Understanding the purpose and structure of a SOC.
- Learning the responsibilities of Tier 1, Tier 2, and Tier 3 SOC analysts.
- Understanding the role of Security Information and Event Management (SIEM) systems.
- Recognizing the importance of alert triage and escalation.
- Understanding how threat intelligence supports investigations.
- Learning how SOC analysts distinguish suspicious events from confirmed incidents.

**SOC analyst responsibilities:**

| SOC Role | Main Responsibilities |
|---|---|
| Tier 1 Analyst | Monitor alerts, perform initial triage, document findings, and escalate |
| Tier 2 Analyst | Conduct deeper investigations and coordinate response activities |
| Tier 3 Analyst | Perform advanced investigations, threat hunting, and detection engineering |

**SOC technologies studied:**

- **SIEM:** Centralizes and correlates security events from multiple sources.
- **EDR:** Monitors endpoint activity and supports investigation and response.
- **IDS/IPS:** Detects or blocks suspicious network activity.
- **Threat Intelligence Platforms:** Provide information about malicious infrastructure and attacker behaviour.
- **Ticketing Systems:** Record investigations, evidence, actions, and escalation decisions.

**Example SOC alert investigation:**

```text
SIEM Alert Generated
        ↓
Review Alert Details
        ↓
Identify Source and Destination
        ↓
Examine Related Logs
        ↓
Check Threat Intelligence
        ↓
Determine Severity
        ↓
Document and Escalate
```

**Illustrative scenario:**

A SIEM generates an alert after detecting repeated failed login attempts against an account.

The analyst investigates:

1. Source IP address.
2. Target username.
3. Number and timing of failed attempts.
4. Whether a successful login followed.
5. Whether the activity is expected or suspicious.
6. Whether escalation or account protection is necessary.

**Security takeaway:** Effective SOC operations depend on accurate alert triage, reliable evidence, clear documentation, and timely escalation.

#### C. Digital Forensics Fundamentals

I studied digital forensics and how investigators collect, preserve, and analyse evidence from computer systems.

**Key learning points:**

- Understanding the purpose of digital forensic investigations.
- Learning the importance of evidence integrity.
- Understanding chain of custody.
- Identifying common sources of digital evidence.
- Learning the difference between volatile and non-volatile data.
- Understanding the role of file hashes and metadata.
- Recognizing why forensic analysis should avoid unnecessarily modifying original evidence.

**Digital forensic evidence:**

| Evidence Type | Examples |
|---|---|
| Disk Evidence | Files, deleted files, partitions, filesystem metadata |
| Memory Evidence | Running processes, active connections, in-memory artifacts |
| Network Evidence | Packet captures, DNS requests, connection logs |
| System Logs | Authentication events, system changes, application activity |
| File Metadata | Timestamps, file size, permissions |
| Browser Artifacts | History, downloads, cached information |

**Important forensic concepts:**

- **Chain of custody:** Documentation of who collected, handled, transferred, and analysed evidence.
- **Evidence integrity:** Ensuring evidence remains unchanged and verifiable.
- **Hashing:** Generating a digest that can help verify file integrity.
- **Metadata:** Information describing a file or digital object.
- **Volatile data:** Information that may disappear when a system loses power.

**Linux forensic commands studied:**

```bash
file evidence.bin
stat evidence.bin
sha256sum evidence.bin
```

**Command explanations:**

- `file` identifies the probable file format.
- `stat` displays file metadata, including size and timestamps.
- `sha256sum` calculates a SHA-256 hash that can be recorded for integrity verification.

**Example integrity verification:**

```bash
sha256sum evidence.bin
sha256sum evidence-copy.bin
```

If the hashes match, the files are highly likely to have identical contents.

**Windows forensic commands:**

```powershell
Get-FileHash .\evidence.bin -Algorithm SHA256
Get-Item .\evidence.bin | Format-List *
```

These commands calculate a file hash and display file properties.

**Security takeaway:** Digital forensics requires a methodical approach to evidence collection, preservation, verification, and analysis. Evidence integrity is essential for reliable investigative conclusions.

#### D. Incident Response Fundamentals

I studied the incident response lifecycle and how organizations prepare for, investigate, contain, and recover from cybersecurity incidents.

**Key learning points:**

- Understanding the difference between a security event and a security incident.
- Learning the importance of incident response plans.
- Understanding the stages of incident response.
- Recognizing how incident severity influences escalation.
- Learning the importance of evidence preservation.
- Understanding why lessons learned are essential after an incident.

**Incident response lifecycle:**

```text
Preparation
     ↓
Detection and Analysis
     ↓
Containment
     ↓
Eradication
     ↓
Recovery
     ↓
Lessons Learned
```

**Incident response stages:**

| Stage | Purpose |
|---|---|
| Preparation | Establish policies, tools, responsibilities, and procedures |
| Detection and Analysis | Identify and investigate suspicious activity |
| Containment | Limit the spread and impact of an incident |
| Eradication | Remove the root cause and malicious components |
| Recovery | Restore affected systems and verify normal operations |
| Lessons Learned | Review the incident and improve security controls |

**Illustrative incident response scenario:**

An employee reports a suspicious email containing a potentially malicious attachment.

The security team may:

1. Record the report and preserve the original message.
2. Examine email headers, sender details, and attachment indicators.
3. Determine whether the attachment was opened.
4. Review endpoint and authentication logs.
5. Contain affected systems if compromise is suspected.
6. Remove confirmed malicious artifacts through approved procedures.
7. Restore normal operations and monitor for recurrence.
8. Document findings and recommend improvements.

**Security takeaway:** Incident response is not only about stopping an attack. It also involves preserving evidence, minimizing business disruption, recovering safely, and preventing similar incidents.

#### E. Logs Fundamentals

I studied how operating systems, applications, and network devices generate logs that help security professionals investigate activity.

**Key learning points:**

- Understanding what logs are and why they matter.
- Identifying common log sources.
- Learning how timestamps, event IDs, usernames, and IP addresses support investigations.
- Understanding the difference between normal and suspicious events.
- Recognizing how logs support SIEM correlation.
- Learning how to filter and search logs using command-line tools.
- Understanding the importance of log retention, synchronization, and integrity.

**Common log sources:**

| Log Source | Security Relevance |
|---|---|
| Authentication Logs | Record login successes and failures |
| System Logs | Record operating system events |
| Application Logs | Record application activity and errors |
| Web Server Logs | Record HTTP requests and responses |
| Firewall Logs | Record allowed and blocked connections |
| DNS Logs | Record domain name queries |
| Endpoint Logs | Record processes, file activity, and security events |

**Linux log analysis commands:**

```bash
cat sample.log
less sample.log
head -n 10 sample.log
tail -n 10 sample.log
```

These commands display log contents and help examine large files.

**Searching for events:**

```bash
grep "Failed password" sample.log
```

This searches a sample log file for failed authentication messages.

**Counting matching events:**

```bash
grep -c "Failed password" sample.log
```

This counts the number of matching lines.

**Monitoring new log entries:**

```bash
tail -f sample.log
```

This follows a log file as new lines are written.

**Windows event log analysis:**

```powershell
Get-WinEvent -LogName Security -MaxEvents 10
```

This displays recent Windows Security log events, subject to appropriate permissions.

**Filtering Windows failed logons:**

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    Id = 4625
} -MaxEvents 10
```

Windows Event ID `4625` represents a failed logon event.

**Other Windows event IDs studied:**

| Event ID | Meaning |
|---|---|
| 4624 | Successful logon |
| 4625 | Failed logon |
| 4634 | Account logged off |
| 4672 | Special privileges assigned to a new logon |
| 4720 | User account created |
| 4740 | User account locked out |

**Example log investigation workflow:**

```text
Collect Relevant Logs
         ↓
Confirm Time Range
         ↓
Filter Relevant Events
         ↓
Identify Accounts and IPs
         ↓
Correlate Related Activity
         ↓
Build an Event Timeline
         ↓
Document Findings
```

**Security takeaway:** Logs provide valuable evidence for detecting suspicious activity, reconstructing timelines, and supporting incident response decisions.
